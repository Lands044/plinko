# Runtime-конфіг Plinko

Лендінг — статичний (без Vite і без збірки): `index.html` + `assets/` + `image/`
+ **`config.json`**. Сторінка читає `config.json` при кожному завантаженні, тож
тексти, виплати, тривалості та CTA змінюються простою заміною цього файлу на
хостингу.

Це статична (production) версія патерну з `config-kit/` — те саме, що лежало б
у `dist/` після `npm run build`.

## Файли

| Файл | Що робить |
|---|---|
| `config.json` | конфіг, який редагують |
| `assets/config.js` | рушій: завантаження, злиття з дефолтами, нормалізація, localStorage (порт `config-kit/core/src/js/config/config.js`) |
| `assets/plinko.config.js` | дефолти гри, нормалізатор (валідація/обмеження), поля панелі |
| `assets/plinko.js` | гра: `render(config)` → DOM, клас `Game`, `mount(config)` для перезапуску наживо |
| `assets/devmenu.js` | панель налаштувань, вантажиться лише коли `dev.menu: true` |

Порядок скриптів в `index.html` важливий: `config.js` → `plinko.config.js` → `plinko.js`.

## Звідки береться конфіг (за пріоритетом)

1. `window.LANDING_CONFIG` — об'єкт, який підставив PWA-хост до завантаження скриптів;
2. `?config=<url>` — перевизначення для конкретного посилання;
3. локальні правки з панелі в цьому браузері (`localStorage`, ключ `config:local`);
4. `config.json`;
5. вбудовані дефолти (`assets/plinko.config.js`) — якщо файл недоступний
   (наприклад, сторінку відкрито через `file://`).

Все, чого немає у файлі, береться з дефолтів, тож частковий конфіг валідний.

## Поля

### `game`
| Ключ | Значення |
|---|---|
| `currency` | валюта в балансі, ставці та спливаючому виграші |
| `balance` | стартовий баланс |
| `bet.min` / `bet.max` / `bet.step` | ставка: стартує з `min`, кнопки ± змінюють на `step` |
| `ctaAfterDrops` | попап після N кидків |

Множники, кількість пінів (12/14/16, за замовчуванням 14), швидкість кульки,
поріг великого виграшу для миттєвого попапу (≥10x), затримки та довжина історії
**не конфігуруються** — вони захардкоджені на початку `assets/plinko.js`.

### `texts`
`logo`, `pinsLabel`, `maxWinLabel`, `betLabel` (до нього дописується валюта),
`popupTitle`, `popupText`, `ctaButton`.

### `cta`
`url` і `target` (`_self` / `_blank`) кнопки в попапі.

### `dev`
| Ключ | Значення |
|---|---|
| `menu` | показувати панель налаштувань (вгорі праворуч, за замовчуванням згорнута) |
| `watch` | опитувати `config.json` і перемальовувати відкриті сторінки при зміні. За замовчуванням `false`: це запит раз на `watchInterval` мс від кожної відкритої сторінки |
| `watchInterval` | інтервал опитування, мс |

## Панель налаштувань

Сервера для запису немає, тому панель завжди працює в режимі **prod**:

- правка одразу застосовується до гри (гра перезапускається);
- зберігається лише в `localStorage` **цього браузера** — інші користувачі її
  не бачать, `config.json` на хостингу не змінюється;
- **«Скачати»** — вивантажує відредагований `config.json` (з коментарями).
  Щоб опублікувати зміни для всіх — замініть ним файл на хостингу;
- **«Скинути локальні зміни»** — повертає те, що лежить у `config.json` на сервері.

Щоб прибрати панель із продакшну — `"dev": { "menu": false }` у `config.json`.

## Додати нову опцію

1. Дефолт у `DEFAULT_CONFIG` (`assets/plinko.config.js`) і в `config.json`.
2. Валідація в `normalizeGameConfig()` там само.
3. Використання в `assets/plinko.js` (`render()` для статичного DOM або клас `Game`).
4. За потреби — поле в `gameFields()`.

## Перевірка локально

`fetch` не працює через `file://`, тому для перевірки `config.json` запустіть
будь-який статичний сервер у корені проєкту, наприклад:

```bash
python3 -m http.server 8000
```
